  # Improve API Usage, Chat UI, and Conversation Memory

  ## Summary

  Refactor the app into a typed backend API with a ChatGPT-like minimal chat window. Keep one POST /api/chat endpoint,
  migrate backend code to TypeScript, preserve task options inside the chat composer, store conversation memory on the
  server in a JSON file, and add one-click response copying.

  ## Key Changes

  - Migrate backend files to TypeScript:
      - Rename app.js to src/server.ts.
      - Move task handlers into src/tasks/.
      - Add tsconfig.json, tsx, and scripts:
          - npm run dev: tsx watch src/server.ts
          - npm start: compile/run or tsx src/server.ts
          - npm run check: tsc --noEmit
  - Keep a single typed API route:
      - POST /api/chat
      - Request: { sessionId: string, mode: "ticket" | "resume" | "review" | "translate" | "summary", prompt: string }
      - Response: { sessionId: string, mode: string, message: { id, role: "assistant", content, createdAt } }
  - Do not create separate task routes yet; use a typed handlers map behind /api/chat.

  ## Conversation Memory
  - Browser creates a sessionId once and stores it in localStorage.
  - Server stores conversations by sessionId:
      - user prompt message
      - assistant response message
      - selected task mode
      - timestamps
  - Add GET /api/conversations/:sessionId to load prior messages on page open.
  - Add DELETE /api/conversations/:sessionId for a “clear chat” button.
  - Add data/ to .gitignore so local conversation history is not committed.

  ## UI Changes

  - Replace the current landing-style layout with a minimal chat interface:
      - Main scrollable conversation area underneath.
      - Fixed or sticky bottom chat composer overlay.
      - Task select inside the composer next to the prompt box.
      - Send button beside the input.
  - Render user and assistant messages as chat bubbles.
  - Long assistant responses scroll in the conversation area, not inside the input panel.
  - Add a copy button on each assistant message using navigator.clipboard.writeText(...).
  - Show lightweight states: sending, copied, error, and empty history.

  ## API Usage Improvements

  - Centralize OpenAI client creation in one backend module.
  - Centralize model name, task modes, and prompt builders.
  - Keep task prompt logic separate from route handling.
  - Validate requests with TypeScript guards before calling OpenAI.
  - Return consistent JSON errors for invalid mode, empty prompt, malformed JSON, and OpenAI failures.

  ## Test Plan

  - Run npm run check.
  - Run syntax/build checks after TypeScript migration.
  - Start npm run dev.
  - Verify homepage loads and restores prior server-stored conversation by sessionId.
  - Verify all task modes call /api/chat and append user/assistant messages.
  - Verify copy button copies assistant response content.
  - Verify clear chat deletes stored history and updates the UI.
  - Verify invalid mode, empty prompt, and malformed JSON return JSON errors.

  ## Assumptions

  - Backend TypeScript only; frontend remains plain browser JavaScript to avoid a bundler.
  - Conversation memory is server-side JSON storage, suitable for local/small use.
  - One /api/chat route remains the primary API because the UI is chat-centered.
  - AGENTS.md remains uncommitted unless separately requested.
